## 一、Agent 实现方法

### 1. 端到端链路
鉴权 → 上传 `dump_info.tar.gz`（内存解压 `app.log`/`framework.log`）→ 双正则解析成结构化条目 → 落盘数据集 JSON → 建会话 → **ReAct agent 对话诊断**。全链路按 `user_id` 隔离。

### 2. ReAct 循环（`backend/agent/core.py`）
- system prompt（注入数据集统计 + 已索引组件）→ LLM → 有 `tool_calls` 则执行工具、回灌结果、继续循环；否则返回文本。
- **三层死循环/撞顶治理**：
  - 最后一轮禁用工具、强制作答（`_FINAL_STEP_DIRECTIVE`），避免撞 `max_iterations`(默认 10) 后只回兜底话术。
  - 同 (工具,参数) 重复且无效达阈值 → 追加"换策略"提示（`_note_tool_result`）。
  - 历史按 token 软预算裁剪（`context_token_budget`，默认 24000），省略最旧工具结果、保留最近 N 条完整证据。
- `run`/`run_stream` 把每条 assistant/tool 消息持久化回 session，支持重启恢复 + 评测轨迹回溯。

### 3. 工具（装饰器注册，按 group 暴露）
- **log 组**（需 dataset）：`search_logs` `filter_by_component` `filter_by_level` `get_summary` `get_time_range` `get_errors_by_component` `get_error_digest` `get_context_around`。其中检索类结果按**消息模板去重聚合**降 token。
- **source 组**（需该用户已建 AST 索引，按 `session.user_id` 暴露）：`get_function_source` `search_symbols` `list_source_files` `summarize_component` `get_file_source` `gather_code_context`。

### 4. 源码根因定位（AST）
`ast_analysis/` 用 **tree-sitter**（C/C++/Lua）克隆组件、解析符号表存 `ast.db` + 源码快照落盘。日志条目带 `file:line` 锚点 → agent 用 `gather_code_context`/`get_function_source` 反查真实函数体、兄弟符号、跨文件调用点，**基于源码证据**给根因，而非凭日志猜测。

### 5. 可观测性
Langfuse v4 OTEL 自动嵌套（chat → react-iteration → llm/tool），trace 本地落盘对账，token 用量（含前缀缓存命中）可观测。

## 二、评测框架（与本版本一同落地）

- **黄金用例** `backend/eval/datasets/golden_cases.json`：13 条 = 10 条源码可定位（pcie_card / ncsi / topo_reader / biz_topo / file_service 等，根因经源码追踪锚定到真实 `file:line`）+ 3 条"未索引组件"负例（certificate / sms_proxy / event_management，考核 agent 是否如实说"需先建索引"而非编造）。
- **指标**（13 项）：
  - 确定性（10）：`diagnosis_acc` `keyword_coverage` `citation_present` `citation_match` `component_named` `expected_tools_invoked` `source_tool_used` `iteration_efficiency` `no_redundant_calls` `tool_call_count`。
  - LLM 裁判（3）：`rootcause_correctness` `faithfulness` `helpfulness`。
- **两种模式均接入 Langfuse**：在线 `run_experiment` → Datasets→Runs（版本对比）；离线 `--offline` → 本地记分卡 + 回灌 Traces（按 `session=eval-<run_name>` 分组）。

### 基线结论
- **优点**：源码工具 100% 使用、工具选择准、几乎无重复调用、建议可执行。
- **待改进**：`rootcause_correctness` / `faithfulness` 明显偏低——agent 会查源码、会引用，但裁判认为根因结论不够准确、对取到的源码证据扣得不够紧（尤其 topology / source-qa 类开放问题）。
- **下一版方向**：强化 system prompt"必须基于取到的函数体下结论、逐条引用证据、避免泛泛而谈"；对开放式 source-qa 收敛工具调用预算。改进效果用同一套指标在 Langfuse 按 run_name 对比验证。
